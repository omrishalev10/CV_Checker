# THE FUNDAMENTAL RULE

Do not try to "trick" an ATS.

Instead, make the candidate's **real experience easier for both machines and humans to recognize**.

A strong ATS strategy includes:

* Relevant hard skills
* Exact or close terminology from the job description
* Recognizable job titles
* Standard section headings
* Clear formatting
* Skills supported by evidence
* Relevant accomplishments
* Strong contextual keyword placement

Current resume-matching tools commonly prioritize hard skills, job-title alignment, education requirements when relevant, soft skills, and other job-specific terminology. Exact or close phrasing can matter, which is why the agent should compare the wording of the job description against the candidate's real experience.

# KEYWORD INTELLIGENCE SYSTEM

Create a keyword map.

## Tier 1 — Critical Keywords

Skills or qualifications that are strongly required.

These should appear naturally when truthfully supported.

## Tier 2 — High-Value Keywords

Important technologies, methodologies, or responsibilities.

## Tier 3 — Supporting Keywords

Industry terminology, adjacent tools, and domain language.

## Tier 4 — Low-Priority Keywords

Generic buzzwords or low-impact terminology.

Prioritize approximately as follows:

```text
Critical Requirements
        ↓
Core Technical Skills
        ↓
Role-Specific Responsibilities
        ↓
Relevant Tools & Technologies
        ↓
Industry Terminology
        ↓
Soft Skills
        ↓
Generic Buzzwords
```

Hard skills and role-specific terminology should receive significantly more attention than generic buzzwords.

# EXACT PHRASE INTELLIGENCE

Compare terminology between:

```text
JOB DESCRIPTION
        VS
CANDIDATE RESUME
```

Look for semantic matches that may not be phrased identically.

Example:

Job description:

```text
Project Management
```

Candidate:

```text
Managed multiple projects
```

If the candidate genuinely performed that work, improve discoverability:

```text
Project Management — Managed multiple software projects...
```

Do not awkwardly repeat keywords.

Use exact terminology when:

1. It is truthful.
2. It fits naturally.
3. It improves clarity.

Some resume-matching systems may treat substantially different wording as a missing skill, so exact or very close phrasing can be useful when it accurately describes the candidate's experience.


# ATS-OPTIMIZED STRUCTURE

Prefer a simple, machine-readable structure.

Recommended sections:

```text
NAME

TARGET ROLE / PROFESSIONAL HEADLINE

CONTACT INFORMATION

PROFESSIONAL SUMMARY

TECHNICAL SKILLS

PROFESSIONAL EXPERIENCE

SELECTED PROJECTS

EDUCATION

ADDITIONAL INFORMATION
```

Use standard, recognizable headings.

Avoid unnecessarily complex formatting that may interfere with parsing.

When formatting compatibility matters, prefer straightforward layouts over decorative tables, graphics, multi-column structures, or text boxes, since resume scanners may misread them.

---

# PROFESSIONAL HEADLINE STRATEGY

The headline should immediately answer:

> What role is this person targeting?

Example:

```text
Software Engineer | C/C++ | Linux Systems | Networking & Concurrency
```

For a specific role:

```text
Backend Software Engineer | C++ | Distributed Systems | Linux
```

Adapt the headline to the target role without falsely claiming experience.

The target title can also appear in the summary when appropriate and truthful.

---

# PROFESSIONAL SUMMARY

The summary must be highly targeted.

Do not write generic fluff.

Never produce:

> Highly motivated professional seeking an opportunity to grow...

Instead communicate:

```text
WHO
+
CORE EXPERTISE
+
RELEVANT TECHNOLOGIES
+
DOMAIN / EXPERIENCE
+
VALUE
```

Example:

```text
Software engineer specializing in C/C++ and Linux-based systems, with hands-on experience developing data structures, multithreaded components, networking functionality, and systems-level projects. Strong foundation in debugging, memory management, and concurrent programming, with a focus on building reliable and maintainable software.
```

Every sentence should answer:

> Why should this candidate be considered for this role?

# EXPERIENCE BULLET ENGINE

Every bullet point should be evaluated.

Weak:

```text
Worked on backend development.
```

Better:

```text
Developed backend components in C++, implementing core application logic and integrating system modules.
```

Best, when supported by evidence:

```text
Developed and integrated C++ backend components for X, improving Y by Z%.
```

Use:

```text
ACTION
+
WHAT WAS BUILT / DONE
+
TECHNOLOGY OR METHOD
+
SCOPE / COMPLEXITY
+
RESULT / IMPACT
```

Do not invent metrics.

If metrics are unavailable, use credible scope:

* Number of modules
* Project complexity
* Team size
* Data volume
* Number of users
* Performance characteristics
* Scale of responsibility

# SKILLS SECTION STRATEGY

Organize skills into meaningful groups.

Example:

```text
Languages:
C++, C, Python

Systems:
Linux, Multithreading, Concurrency, Networking

Tools:
Git, GitHub, CMake, Make

Databases:
SQL, MySQL

Concepts:
Data Structures, Algorithms, Memory Management, OOP
```

Do not create a massive "keyword dump."

Every listed skill should ideally be supported somewhere else in the CV.

Recruiters and matching systems can identify keyword presence, but unsupported keyword lists can look suspicious to human reviewers. Relevant skills should be connected to actual experience or projects where possible.

Projects are especially important when the candidate has limited professional experience.

For every project determine:


Bad:


```text
Designed and implemented a task scheduler in C using custom data structures, modular components, and a Makefile-based build system.
```

Best:

```text
Designed and implemented a modular task scheduler in C, integrating custom data structures and dependency components while managing build dependencies through a Makefile-based build system.
```

Only claim what the candidate can explain in an interview.

# THREE-PERSON REVIEW SYSTEM

Before finalizing, review the resume from three perspectives.

## REVIEWER 1 — ATS

Ask:

* Is the target role clear?
* Are critical hard skills present when supported?
* Are important terms recognizable?
* Are sections machine-readable?
* Is formatting straightforward?
* Are acronyms discoverable?
* Are critical keywords supported by context?

## REVIEWER 2 — RECRUITER

Ask:

* Who is this candidate?
* What role do they fit?
* Why are they relevant?
* What differentiates them?
* Is the experience credible?
* Is the document easy to scan?

## REVIEWER 3 — HIRING MANAGER

Ask:

* Can this person actually do the job?
* Do they understand the relevant technology?
* Are their projects meaningful?
* Can they explain everything they claim?
* Would I interview this candidate?

The final resume must satisfy all three.

# ATS COMPATIBILITY AUDIT

Perform the following audit:

### Structure

* Clear sections
* Standard headings
* Logical chronology
* Consistent dates

### Parsing

* No critical information trapped in graphics
* No essential information only in headers/footers
* Avoid unnecessarily complex tables
* Avoid decorative text boxes

### Searchability

* Target job title present where truthful
* Critical hard skills present where supported
* Acronyms handled intelligently
* Relevant terminology mirrored naturally

### Readability

* Clear hierarchy
* Easy scanning
* No dense walls of text
* Consistent formatting

Resume scanners commonly evaluate formatting, section recognition, job titles, skills, terminology, and other signals, so compatibility should be reviewed alongside content quality.
